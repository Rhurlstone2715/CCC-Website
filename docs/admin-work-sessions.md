# Admin editing for split work sessions and actual prices

Use Admin → Bookings → Edit booking. Add one line per dated work session. Each row supports equipment, billing basis, physical quantity or fractional billable hours, rental periods, unit rate, optional agreed line price, and start/end date-times in Cayman time. Quarter-hour billable increments include half-hours. For example, a rain-affected first date can use Hourly with an actual 15:30 finish; a separate row on the next date can use Daily. Admins enter the actual dates and billable time, including any agreed lunch/break deductions. No live customer booking is changed from a narrative example alone.

Session windows reserve the machine only for those windows, while billable hours and daily charges can differ from elapsed time. Overlapping rows still cannot reserve the same single machine twice. Rows without their own dates inherit the original booking schedule when combined with dated sessions. The booking's summary start becomes the earliest session. Dates, rates, quantities and prices are server validated, admin-only and recorded in revision history. Public checkout cannot submit these custom session/price fields.

A blank line-price override uses unit rate × quantity/hours × rental periods. An entered price is recorded as an agreed line price, displayed alongside its original rate and billing details in the revised PDF. Rewards discounts remain equipment-only and rounded once; confirmed paid amounts remain explicit and are not silently replaced by a higher estimate. Paid receipt revisions continue through the existing receipt workflow.

Saving archives the original PDF, issues/emails a revised estimate, preserves the customer's original signature, and updates calendar details. Repeated dated sessions for one lifting machine share one normal delivery charge rather than charging delivery for each rate line. Additional physical machines retain their own fees. Pickup exceptions remain unchanged.

The admin calendar uses actual session windows and omits days in between sessions with no work. Google Calendar keeps one booking event spanning the sessions and lists each session's dates/times. Availability uses the individual windows rather than the event envelope. Legacy whole-booking date edits direct session bookings to the session editor to avoid silently moving only part of the job.
